# Ingestion API v1 (Contract A in practice)

`POST https://<project-ref>.supabase.co/functions/v1/ingest`

Headers: `Authorization: Bearer cdx_<64 hex>` and `Content-Type: application/json`. Use the key only from servers.

Body: `{ "events": [ ... ] }` (up to 100 events, 512 KB total). An array or a single event is also accepted.

Event fields (anything else is rejected):
| Field | Rules |
|---|---|
| `event_id` | required, UUID, used to ignore re-sends |
| `type` | required: `error`, `custom`, `http`, `log` |
| `severity` | `debug`, `info`, `warning`, `error`, `fatal` (defaults to `error` for errors, `info` otherwise) |
| `occurred_at` | required, ISO 8601 with a time zone, between 7 days ago and 5 minutes ahead |
| `name` | optional, up to 200 characters |
| `trace_id`, `span_id` | optional, up to 64 characters of `A-Z a-z 0-9 _ . : -` |
| `attributes` | optional flat object, up to 64 keys, key up to 64 characters, values string (2,048), number, boolean or null |
| `error` | required for `type: error`: `type`, `message`, optional `stack` (16,000) |
| `sdk` | optional: `name`, `version`, `language` |
| `schema_version` | optional, must be 1 |
An event is at most 32 KB. The project and environment come from the key, never from the body; `received_at` is set by the server.

Responses (always JSON, never cached):
| Status | Meaning |
|---|---|
| 200 | `{ accepted, duplicates, rejected: [{index, reason}] }`. Bad events are listed and the good ones are stored |
| 400 | invalid JSON, no valid events, or a data error |
| 401 | missing, malformed, unknown or revoked key |
| 413 | body over 512 KB or more than 100 events |
| 415 | not JSON |
| 429 | `rate_limited` (retry after the `Retry-After` seconds) or `quota_exceeded` (monthly limit) |
| 503 | the database could not be reached; retry |

Protections: keys are stored only as SHA-256 hashes; passwords, tokens, keys, JWTs, bearer values and card numbers are removed before storage; 6,000 events per key per minute; a client that sends 30 bad keys in 10 minutes is blocked for the rest of that window; a default monthly cap of 100,000 events per project (D-17); a refused batch stores nothing.

Error groups: error events with the same type, message (numbers and ids ignored) and top stack frame (line numbers ignored) form one group. A resolved group reopens when it happens again; an ignored one stays ignored.

## Examples
The Setup page shows ready-to-paste examples for PowerShell, Command Prompt, Bash, Node.js, TypeScript and Python, pre-filled with your key. They are generated by `src/lib/snippets.ts`, and `src/lib/snippets.test.ts` runs the Bash, Command Prompt (through curl), Node.js, TypeScript and Python examples against a local server and checks every request body with the real validator. The PowerShell example cannot be run on the test machine, so its body is checked structurally; please confirm it once on a real Windows machine.

## Browser access (CORS)
Off by default: browsers are blocked. Set the function secret `CORS_ALLOW_ORIGINS` to a comma-separated list of exact origins (`https://app.example.com`) to allow them. Entries with `*` or a path are ignored. Keys are still secrets; put one in browser code only for a dedicated, low-cap project such as this app's own self-monitoring (see the README).
